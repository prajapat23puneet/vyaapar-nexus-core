       - Query: SELECT * FROM outbox_messages

6.10 Implement consumers (Choreography pattern via MassTransit):

     OrderCreatedConsumer.cs:
       - Idempotency: insert inbox_message, skip if duplicate
       - Check ForceFailure flag from message payload
       - If ForceFailure=inventory:
           Update order.status = InventoryFailed → OrderCancelled
           Update saga: current_state = OrderCancelled, last_error = "Forced inventory failure"
           Write SagaEventLog entries: InventoryFailed, OrderCancelled
           Write NO outbox (terminal)
       - Else:
           Acquire distributed lock per product (sorted by productId)
           Check stock sufficient for all items
           If insufficient:
               Release all locks
               Update saga: InventoryFailed → OrderCancelled
               Write SagaEventLog entries
           Else:
               Decrement stock for all items (in transaction)
               Release all locks
               Update saga: current_state = InventoryReserved,
                            inventory_reserved = true
               Update order.status = InventoryReserved
               Write SagaEventLog entry
               Write OutboxMessage for PaymentProcessRequested
       SaveChanges()

     PaymentProcessRequestedConsumer.cs:
       - Idempotency check
       - Update saga: current_state = PaymentProcessing
       - Update order.status = PaymentProcessing
       - Write SagaEventLog entry
       - Check ForceFailure flag OR CircuitBreaker state
       - If payment circuit is OPEN:
           failure reason = "Payment circuit open"
           goto payment failure
       - Else call PaymentService.ProcessAsync()
       - If ForceFailure=payment OR PaymentService returns failure:
           Update saga: current_state = PaymentFailed, last_error = reason
           Update order.status = PaymentFailed
           Write SagaEventLog entry
           Write OutboxMessage for InventoryReleaseRequested
       - Else:
           Update saga: current_state = PaymentProcessed, payment_processed = true
           Update order.status = PaymentProcessed
           Update order.payment_reference = reference
           Write SagaEventLog entry
           Write OutboxMessage for ShippingDispatchRequested
       SaveChanges()

     InventoryReleaseRequestedConsumer.cs (compensation):
       - Idempotency check
       - Restore stock: UPDATE products SET stock_quantity += qty
       - Write SagaEventLog entry (InventoryReleased)
       - Update saga: current_state = OrderCancelled
       - Update order.status = OrderCancelled, cancelled_at = NOW()
         failure_reason = stored last_error or payment reason
       - Compute duration_ms if possible
       - Write SagaEventLog entry (OrderCancelled)
       - Increment orders_cancelled_total Prometheus counter
       - No further outbox messages (terminal)
       SaveChanges()

     ShippingDispatchRequestedConsumer.cs:
       - Idempotency check
       - Update saga: current_state = ShippingDispatching
       - Update order.status = ShippingDispatching
       - Call ShippingService.DispatchAsync()
       - Update saga: current_state = ShippingDispatched, shipping_dispatched = true
       - Update order.status = ShippingDispatched
       - Write SagaEventLog entries
       - Write OutboxMessage for NotificationSendRequested
       SaveChanges()

     NotificationSendRequestedConsumer.cs:
       - Idempotency check
       - Call NotificationService.SendAsync() (log only)
       - Update saga: current_state = OrderCompleted,
                      notification_sent = true,
                      completed_at = NOW(),
                      duration_ms = NOW() - started_at ms
       - Update order.status = OrderCompleted, completed_at = NOW()
       - Write SagaEventLog entries (NotificationSent, OrderCompleted)
       - Increment orders_completed_total Prometheus counter
       - Record saga_duration_ms histogram observation
       SaveChanges()

BUILD ORDER RULES (REPEAT FOR AGENT)
════════════════════════════════════════════════════════════════════

1. Never build frontend components before the API endpoint they consume exists.
2. Never build saga consumers before message contracts are defined.
3. Never build message contracts before domain entities and DB are ready.
4. Never skip an exit gate — each exit gate is a forcing function to prevent
   compounding broken state.
5. When in doubt about a spec, refer to prd-agent-v2.txt — it is the truth.
6. The SSE stream must be working with real data BEFORE the frontend
   SSE hook is written — never build the consumer before the source.
